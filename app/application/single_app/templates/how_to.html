Overview

This application provides secure, context-aware AI assistance for the DeCA workforce. It supports both personal and group workspaces, citations to your sources, and user feedback. The system uses Retrieval-Augmented Generation (RAG) so answers can be grounded in the documents you provide.

Users may upload documents in Personal Workspace (private) or Group Workspaces (shared). Uploads can include common document formats such as txt, pdf, docx, xlsx, xls, csv, pptx, html, jpg, jpeg, png, bmp, tiff, tif, heif, md, json.

Quick Start (for users familiar with NIPR/AskSage-style tools)

  1. Open Personal Workspace or a Group Workspace aligned to your team’s mission.
  2. Drag and drop files or Click Browse and add reference documents (policies, SOPs, memos). This system works best with text-based PDFs/.doc files.
  3. Go to Chat, select Search Workspaces, select Scope and Document, then ask a question and review the citations under each answer before acting.
  4. Iterate: clarify the task, provide constraints, and request a specific output format (e.g., bullet memo, email draft).

Personal Workspace vs Group Workspaces

  • Personal Workspace: personal drafts and research; only you can see the uploads.
  • Group Workspaces: shared sources and prompts for a team; promotes consistent answers and reduces rework.
  • Use descriptive filenames and logical workspace names to improve retrieval and citation clarity.
Data Handling: Respect the classification banner at the top of the site. Do not upload material beyond the authorized level.

Uploading Files & Citations

  • Supported formats include txt, pdf, docx, xlsx, xls, csv, pptx, html, jpg, jpeg, png, bmp, tiff, tif, heif, md, json and markdown
  • Due to the nature of LLMs the system naturally prefers text-based Word Docs and PDFs with clear headings. Split very large documents into logical parts for better retrieval.
  • For ephemeral use, upload directly in Chat; these items will not persist past the current session.
Upload only material authorized for the system’s classification and mission use. Remove drafts that are no longer required.

Human-in-the-Loop (HITL)

This tool assists; it does not replace judgement. For official outputs, validate citations and ensure the content meets policy, legal, and classification requirements.

  • Review citations and compare to source passages.
  • Revise prompts to correct tone, scope, and format (e.g., leadership memo vs. technical note).
  • Record feedback using the built-in feedback controls; admins can review and improve system behavior over time.
  • Escalate edge cases to your supervisor or Admin when policy interpretation is required.

Explore & Learn

The best way to learn is to iterate. Try the following exercises:

  1. Upload one short memo, ask for a 5-bullet summary, then ask for a briefing slide outline with citations.
  2. Move the same memo into a Group Workspace and have a teammate review the outputs for consistency.
  3. Prompt the model to identify assumptions and unknowns and propose targeted follow-up questions.

Prompt Engineering (Practical)

Here is a classic prompt engineering core pattern. This is a good way to begin a new conversation, if you already have a clear goal in mind.

  1. Role & Audience: “You are a staff analyst preparing content for SES leadership.”
  2. Objective: “Produce a one-page summary with three decision options.”
  3. Sources: “Cite only from the active workspace; if missing, state ‘source not found.’”
  4. Constraints: “Plain language; IL4-appropriate; no PII; bullet format; 250–300 words.”
  5. Output: “Return: (1) 5 bullets; (2) risk table: risk/likelihood/mitigation; (3) next steps.”
  6. HITL Step: “List assumptions and unresolved questions for human review.”

Starter Templates

Leadership Summary

Prepare a one-page summary for senior leadership on <topic>.
Constraints: IL4 wording, no PII, bullet format, 250–300 words.
Deliver: 5 bullets, a 3-row risk table (risk/likelihood/mitigation), and 3 immediate next steps.
End with 3 assumptions and 2 questions for the human reviewer.

Policy Comparison

Compare Policy A vs. Policy B.
Return a two-column table (A vs. B) with: scope, authority, key requirements, enforcement, citations.
Call out conflicts and missing sections; flag items needing legal review.

Draft Memo/Email

Draft a formal memo to <office> announcing <initiative>.
Tone: government; concise; active voice.
Include: purpose, background, action required, suspense date. Cite relevant directives when available.

Quality Checks

  • Ask for a second pass focusing on accuracy, tone, and missing citations.
  • Instruct: “If no source is found for a claim, say ‘no source in workspace’ instead of inferring.”
  • When the answer aggregates multiple documents, request a sources-to-claims table.

Troubleshooting

  • No citations? Confirm you’re in the correct workspace and the files finished processing.
  • Old or generic answers? Start a new chat and restate the goal with constraints and format.
  • Access issues? Check your role under My Account or contact an Admin.
  • Content blocked? Content Safety may be enabled; rephrase in mission-appropriate, non-sensitive terms.
For persistent issues, coordinate with the Admin team.
